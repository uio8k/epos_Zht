# 文档托管决策（D-D1 – D-D8）

日期：2026-11-12。授权来源：用户原话「我只需要管 progress.html，其余所有文档交给 dsh 管理，更新」（六问 grill 逐条确认）。

本文件是**文档归属与维护方式的单一事实源**。其他文档只引用不复述；与本文冲突的旧表述一律以本文为准，并在原处加〔已废止 → 见 D-Dx〕标注（D-D2）。

## 1. 文档归属表

| 文档 | 角色 | 人工可改 | 维护者 |
|---|---|---|---|
| `progress.html` | **唯一人工界面**：进度、用例状态、测试分层、文档健康 | 只读/临时勾选 | DSH 按轮写入，随提交落盘 |
| `AGENTS.md`（外层） | 交差硬规矩（怎么算完成） | 可加不可删 | DSH 随流程变更追加 |
| `CODEBUDDY.md`（外层） | 架构与常用命令 | 可加不可删 | DSH |
| `README.md`（内层） | 驱动说明入口 | 可加不可删 | DSH |
| `docs/decisions-*.md` | 定案与理由 | **只追加** | DSH（新条目），旧条目只加废止标注 |
| `docs/tech-plan-*.md` | 每项工作的方案 | 只追加 | DSH（开工前写，落地后回填实测） |
| `docs/evidence/<日期>/` | 原始证据（命令原文、退出码、日志） | **append-only** | DSH（不删不改既有证据） |
| `.dsh/skills/autodev/SKILL.md` | autodev 流程本体 | 否 | DSH（改完同步 `.zcode` 镜像） |
| `.zcode/skills/autodev/SKILL.md` | 上述的镜像 | 否 | 由 `.dsh` 同步而来 |

## 2. 决策

### D-D1 唯一人工界面 = `progress.html`
用户只读这一页。其余文档的存在意义是给 DSH 与将来的自己留推理链（为什么这么定、怎么验的），**不需要人工评审**。判断「项目现在什么状态」只看 `progress.html`；判断「依据是什么」再看 `docs/`。

理由：此前用户需要同时读 5 份 decisions + 6 份 tech-plan + 113 个证据文件才能拼出全貌，而其中 6–8 处已经和实况脱节——多文档没有带来可信度，只带来了漂移。

### D-D2 `decisions-*.md` 只追加，过期处加废止标注
新决定写新条目（D-A13、D-D8…）；被推翻的旧条目**保留原句**，单元格内追加〔已废止 → 见 D-xx〕。理由：决策记录的价值在于能回看当时的取舍，改写它等于伪造历史；而删掉它会让后来的读者不知道某条规则为何消失。

### D-D3 autodev 取消「git 提交」干预点，一律自动提交
用户明确选择最激进档：**连代码轮也不问**。提交后汇报 commit hash + `git show --stat`，不请求确认。仍保留的硬干预点见 D-A13。push 依旧手动（远端是不可逆外扩，与本地提交不同级）。

前提（D-D8）：开工树必须干净。`git status --short` 有**他人/并发会话**的改动时停下报备，不得替别的会话提交。

### D-D4 防漂移靠可执行检查，不靠自觉
`tools/check_docs.py`（C1–C10）+ `make docs-check`，并置于 `make full` 首位——文档没对齐就不该谈测试全绿。

判定与 `tools/check_progress.py` 同一范式：**状态只存一处**（页面 `data-*` 属性），**判定只此一处实现**（脚本），页面上的结论句由脚本核对而不是人工复查。

### D-D5 页面新增 ④ 文档健康，由 `--sync` 生成
块内是文档归属表 + 每份文档最后更新时间 + 失效引用数 + 一行自检结论。块体由 `tools/check_docs.py --sync` 写入，`make docs-check` 的 C7 逐字校验保真——**手改会被判红**。

有意设计：块里嵌了通过计数，任何检查结论变化都会让 C7 红并要求重新 `--sync`。宁可多跑一次命令，也不允许页面声称的状态与脚本判定分叉。

### D-D6 文档同步嵌进 autodev 每轮（§7.5）
位置在「§7 证据核」之后、「§8 提交」之前：跑 `make docs-check` → 按 FAIL 修文档 → `--sync` 重生成 → 再跑到绿 → 证据落 `docs/evidence/<日期>/docs-check-*.log`。零新入口，用户不需要记新命令。

### D-D7 证据 append-only
`docs/evidence/` 下既有文件不删、不改、不整理归档。改错了就再落一份，文件名带轮次后缀（如 `-fix1`）。理由：证据是唯一能推翻结论的东西，一旦可编辑就失去证明力。

### D-D8 自动提交的前提：树净
见 D-D3 前提。另：`git status --short` 出现 `kernel/`、`userapp/`、`tests/*.c` 而本轮任务不是代码轮时，说明范围溢出，必须回退或报备。

## 4. 不做什么

- 不做文档自动生成器（不把 tech-plan 的内容由脚本从代码抽取）——方案文档的价值在推理过程，代码抽不出来。
- 不清理、不归档 `docs/evidence/` 历史（D-D7）。
- 不新增 P 项：文档托管是流程基建，不是开发任务（沿用 `docs/decisions-autodev.md` §4 先例）。
- 不引入第三方依赖：`tools/check_docs.py` 纯标准库，Python 3.7 兼容。
