== 摘录 3 结论 ==
1) 驱动名由环境变量 QEMU_AUDIO_DRV 取（:1898 audio_get_conf_str），
   故 3.1.x 上「切 none 后端」= 设 QEMU_AUDIO_DRV=none，与 -audio-help 输出一致。
2) 即便不设该变量，代码最后也有硬兜底：audio_driver_lookup("none")（:1921-1924），
   并打印 warning: Using timer based audio emulation。
   => 本机无宿主音频设备时 QEMU 不会因音频初始化失败而退出，none 是天然兜底。

== 摘录 4 结论 ==
采集侧数据源是 AUD_read(st->voice.in, ...)（:271），即 SWVoiceIn 从 HWVoiceIn 取数。
在 none 后端下 HWVoiceIn 正是 noaudio.c 的 no_read()（摘录 1），返回清零缓冲。
=> hda-duplex + QEMU_AUDIO_DRV=none 时，guest 的采集 DMA 会持续搬入全 0 样本：
   采集字节数/中断/停流时序等【行为级】判据全部可测，仅【样本值】恒为静音。

== 五条摘录的合并结论（P10 可行性）==
1. none 后端 = 定时器模拟音频：播放和采集两边都按 QEMU_CLOCK_VIRTUAL 推进，
   链路与 DMA 全跑，仅样本内容无真实声源（摘录 1/2）。
2. 采集侧 no_read() 返回"清零过的 to_clear 字节"，长度与时间成正比 ——
   可断言"采集字节数在合理区间""停流后不再增长"，但不能断言样本内容。
3. hda-duplex 在 none 后端下照常创建 SWVoiceIn/HWVoiceIn（摘录 4），
   故整机测试无需宿主声卡即可跑完整条采集链路。
4. 环境变量是 3.1.x 唯一入口（无 -audiodev，那是 4.2+），Makefile 里用
   QEMU_AUDIO_DRV=none 前缀即可，不改 QEMU（D8）。
